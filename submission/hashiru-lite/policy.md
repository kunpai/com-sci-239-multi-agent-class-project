P1. Before an agent calls hire_agent, it must call check_usage on its own pool in an earlier LLM turn, and its most recent such check must show at least the budget_usd it is about to reserve and, if the new agent runs on a local model, at least that model's size in free memory. The check goes stale, and the agent must check again before hiring, if the agent itself has hired anyone since that check or if any agent has hired on a local model since, because all local models share one machine's memory. A check issued in the same LLM turn as the hire does not count, since the model decided the hire before it saw the result, and a check that returned an error does not count. A cloud hire by a different agent does not make the check stale.

P2. An agent's own LLM spending plus what the agents it hired hold must never exceed the dollars reserved for it; for the CEO this is the whole budget, BUDGET_USD. A live hired agent holds its whole reservation. A fired agent holds what it and every agent below it actually spent, because API dollars are not refunded. This applies at every level of the hiring tree, after every LLM call and every hire. Calls to local models cost nothing.

P3. Results of read_file and memory are private, and only agents on local models may receive them. A cloud agent must never receive private data, whether as its own tool result or relayed in a message, reply or hire prompt from an agent that holds private data. An agent that holds private data must not call get_website and must not hire an agent on a cloud model. An agent holds private data from the moment it receives any until the task ends. Exceptions: deliver_to_user may receive private data, because it goes straight to the user; a reply of exactly "done" or "failed" carries no data; and a read_file or memory call that returned an error produces no private data.

P4. Once an agent holds untrusted content in a task, it must not hire any more agents in that task. Content is untrusted if it came from get_website, or from a message, reply or hire prompt sent by an agent that held untrusted content. The agent may still fire agents, message agents it already hired, and deliver results to the user.

P5. An agent may call check_usage only on its own pool, which is named after the agent. This applies to the CEO too: it must not check the pools of the agents it hired.
