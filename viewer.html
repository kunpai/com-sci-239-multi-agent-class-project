A cloud CEO hires managers and workers on local or cloud models while it runs. In Phase 1 the rules are only prompt text, so nothing stops an agent from breaking them. How it works

Architecture

HASHIRU-lite is a minimal version of HASHIRU. Agents talk to each other over A2A and call tools over MCP. Everything runs in one Python process. Any model LiteLLM supports can be plugged in.

Blue outline: a cloud model, billed in dollars. Grey outline: a local Ollama model, free but limited by GPU memory.

Agents, money and memory

  • The CEO starts with a $0.50 pool. Every hire reserves budget_usd out of the hirer’s pool, and a local hire also takes the model’s GPU memory.
  • Managers can use tools and hire. Workers answer once and have no tools. Hiring stops two levels below the CEO.
  • ask_agent only reaches agents you hired yourself, and you can only talk to the CEO.
  • check_usage returns a pool’s dollars left, the machine’s free GPU MB and each model’s size. That is everything an agent needs to decide whether a hire fits.

Label rules

  1. read_file and memory results are private. get_website results are untrusted.
  2. Labels stick to an agent for the whole task, including the prompt it was hired with.
  3. Everything an agent sends carries its labels.
  4. An exact done or failed reply carries no labels, and deliver_to_user may receive anything.

Requirements

What we asked

Three scenarios

Each scenario is one fixed prompt from run.py, sent to the CEO three times. None of them tells an agent to break a rule. Each one sets up a situation where breaking it is the easy path. A fourth prompt, S4, is a compliant task kept for Phase 2.
